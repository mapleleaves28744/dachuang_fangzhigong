📢 答辩核心话术
================================================================================

【问题 1】为什么要从 TF-IDF 改造到 Dense Vector?

答:
"传统 TF-IDF 基于字面匹配,存在两大问题:

1. 无法理解语义。比如用户问'导数求法'和'微分规则'
   是语义相同的,但 TF-IDF 看不出来。

2. 措辞变化导致召回率低。只要用户换个表述方式,
   系统就可能找不到相关知识。

我们采用 Dense Vector RAG:使用 BGE 语义模型将
60,000 条知识转化为 384 维稠密向量,存储在 FAISS
中。这样系统就能真正理解语义含义,提高召回率约 30%。"


【问题 2】FAISS 相比其他向量数据库的优势?

答:
"我们选择 FAISS 因为:

1. Meta 官方维护,生产级质量,被 Facebook 等大公司
   在线使用。

2. 毫秒级延迟。FAISS 的 IndexFlatL2 在 60K 向量
   上搜索仅需 50ms,完全满足实时需求。

3. 跨平台无缝部署。纯 Python + NumPy,不依赖外部服务,
   完全本地化。

4. 我们衡量过其他方案(Milvus/Weaviate),但对于
   本地部署的学生项目,FAISS 是最优平衡。"


【问题 3】系统的真实应用场景?

答:
"设想一个学生在复习微积分时的真实场景:

学生问: '为什么导数可以判断函数单调性?'

系统流程:
1. 用 BGE 模型理解question的真实意图(不仅是关键词)
2. FAISS 检索出语义相关的知识:
   - 微积分基本定理
   - 这种情况下的应用
   - 反例和边界条件
3. Neo4j 图谱补充关系: 导数 ← → 单调性
4. 生成融合答案: '因为f'(x)>0表示...'

这是 RAG + Agent 的真正威力:不是简单检索,
而是融合多源知识进行推理。"


【问题 4】系统有什么创新点?

答:
"我们的核心创新:

1. Dense Vector RAG 不是新概念,但我们将其完整落地
   到K12教育场景,这是创新应用。

2. 混合权重架构: FAISS(35%) + 词法(25%) + 图(20%)
   + 私有(20%),没有单一依赖,鲁棒性强。

3. 性能优化: BGE-small 而非 BGE-large,保持
   建立时间<30min,个人电脑即可运行。

4. 教育适配: 自动学科路由,针对数学/物理/英文等
   不同学科调整权重,提升准确度。"


【问题 5】系统能扩展到更大规模吗?

答:
"可以,方向:

1. 数据规模: 从 60K 扩展到 6M chunks,FAISS
   支持增量索引,只需加一个 GPU 即可达到毫秒级。

2. 实时更新: 引入流式索引,新增知识无需全量 rebuild。

3. 多模态: 知识库早期准备了图像字段,可直接
   升级为视频 + 文本 RAG。

4. 商业化: 构建市场,可针对不同学科/级别做
   精细化知识库,按需销售。"
