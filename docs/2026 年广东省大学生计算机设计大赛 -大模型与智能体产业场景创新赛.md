

2026 年广东省大学生计算机设计大赛
-大模型与智能体产业场景创新赛

本科组赛题说明

一、赛题内容
智能体系统设计与开发——面向产业与教育的大模型应用实践
本赛题要求参赛选手利用成熟的大模型（如 DeepSeek、通义千问等开源模型，或通过API 调用的豆包、文心一言等）作为“智能大脑 ”，结合检索增强生成（RAG）、工具调用、智能体工作流等前沿技术，面向服装、珠宝、时尚潮玩、教育四大领域（选其一即可），设计并实现一个能解决该领域实际痛点、具备完整架构与明确价值的智能体原型。
二、竞赛任务说明
2.1 作品设计场景
① 产业方向（服装、珠宝、时尚潮玩等）：

场景一：产品外观设计（例如珠宝外观设计）
场景描述：珠宝行业存在"创意产出慢、设计同质化严重、个性化定制成本高、生产工艺复杂难优化"等痛点。通过快速生成新颖设计、精准匹配用户需求、自动优化工艺结构，并大幅降低从概念到产品的周期与成本，让高品质、个性化的珠宝设计变得更加高效。

场景二：营销智能体（例如数字人、营销素材生成或获客等）
（1）数字人：真人主播面临时间限制、成本高昂、稳定性不足等问题。开发一套创新的AI 数字人直播带货系统，实现 7×24 小时智能直播、个性化互动、高效转化的直播电商新范式。
（2）营销素材生成：在数字营销时代，同一件产品需适配电商详情页、社交媒体、直播短视频等数十种场景，对创意内容的海量需求与高度个性化提出了极限挑战。以 AI 驱动构建一个懂产品、懂用户、懂平台的AI 营销内容智能体，实现从产品卖点到爆款内容的端到端生成。
（3）获客：行业全域流量面临着从"流量红利"到"流量焦虑"的转变， 目标客群高度分散且难以精准定位，获客成本（CAC）极高且持续攀升。以 AI 驱动获客，从精准度、相关性、信任度维度完成从线索发现—接触互动—引导转化的全流程。




场景三：电商数据分析（例如跨平台用户分析、产品评价分析等）
场景描述：数字贸易时代，营销遇见三大困局：（1）流量贵如金，浪费如流水；（2）价格战绞肉机，利润薄如纸；（3）用户善变如风，忠诚度是神话。以AI 驱动构建一个能够实时理解用户、预测需求、触发动心时刻的下一代用户画像引擎，实现从"盲目搏杀"到"精准制导"，破解行业困境。

场景四：外观缺陷检测（例如珠宝外观检测）
场景描述：珠宝的完美外观是其价值核心。传统质检依赖人工放大镜，存在效率低、标准不一、易疲劳等问题。构建一个能"像资深工匠一样看"的 AI 智能体，不仅需识别微观缺陷，还需推断缺陷成因，为工艺优化提供决策支持。

场景五：行业客服智能体（例如服装电商客服）
场景描述：服装电商客服面临三大痛点：1）70%的咨询与尺码、退换货相关，重复劳动严重；2）负面情绪用户（特别是退货场景）难安抚，易升级为投诉差评；3）客服仅为成本中心，无法创造转化价值。构建一个能精准理解用户意图、共情安抚情绪、并在服务中主动创造价值的智能客服系统，实现从"被动解答"到"主动服务与增值"的转变。

② 教育方向：
● 助教（教学辅助）：辅助教师完成课件生成、作业批改、答疑解惑等教学环节
● 助学（学习支持）：为学生提供个性化学习路径规划、知识点讲解与练习生成
● 助评（评价与反馈）：构建智能评测体系，对学习成果进行多维度评价与反馈
● 助管（教学管理）：协助管理教学资源、学生信息、课程安排等管理事务
● 助育（育人辅助）：关注学生心理健康、综合素质培养及德育辅助

三、挑战规则


3.1 软件环境
● 基础模型：任选至少一种主流大模型（如DeepSeek、通义千问等开源模型，或通过API调用的豆包、文心一言等）作为智能体的核心。
● 开发框架：推荐使用 LangChain、LlamaIndex、Semantic Kernel、 OpenClaw 等主流智能体应用框架，或自行构建工程化架构。
● 部署环境：本地服务器或云服务器，支持 Python 环境，鼓励容器化部署。
3.2 任务要求
参赛团队需从服装、珠宝、时尚潮玩、教育四大方向中任选其一，完成一个完整的智能体系统开发项目。具体要求如下：
领域聚焦与架构设计：
清晰定义拟解决的具体产业或教育场景问题，并设计出包含智能中枢、知识库、工具调用、交互界面在内的完整系统技术架构。
核心技术实现：
● 检索增强生成：必须实现基于领域知识的 RAG 功能，构建并应用专业向量知识库。
● 工具调用与工作流：必须实现至少一种外部工具或API 的有效调用（如数据查询、图像生成、计算工具等），并能将其融入智能体的推理与决策流程。
● 系统集成开发：开发可稳定运行的应用Demo，包含完整的后端服务与前端交互界面。
优化与创新：
鼓励在系统性能（如 RAG 检索精度、响应速度）或应用创新性（如交互模式、多模态融合）上进行优化与探索。
3.3 技术要求
● 系统须以选定的开源大模型为核心，结合 RAG 与工具调用等关键技术。
● 智能体需具备清晰的角色设定与专业领域边界。
● 系统应具备良好的安全性、稳定性及用户体验。
● 鼓励对本地部署的模型进行推理优化（如量化、加速），但非强制要求。
3.4 发布要求
● 最终作品须为一个可独立运行、功能完整、支持交互演示的智能体系统原型。
● 需提交全部源代码、依赖环境配置、模型权重获取说明（如 HuggingFace 下载链接）及详细的部署说明
● 系统应在评审现场能成功部署并稳定演示核心功能，或有视频演示支持。
3.5 现场答辩


为确保公平，本赛题现场评审时，将针对所有选手采用统一的现场演示及 PPT 答辩环节。演示需基于团队提交的可运行系统进行。
3.6 拓展动作
鼓励参赛团队在核心技术框架内，探索以下方向：
● 自制或精细构建高质量的领域训练数据与知识库。
● 尝试智能体规划、反思等更复杂的工作流机制。
● 进行有深度的性能优化与工程创新。
● 实现跨领域、跨模态的融合应用。

五、竞赛软硬件平台及其技术参数
5.1 开发平台
① 基础大模型（核心智能引擎）：
必须使用开源可商用许可的大模型，例如豆包、DeepSeek、通义千问等。
可通过 Hugging Face、ModelScope 等平台获取，支持本地部署或云端 API 调用（若使用API，需在文档中说明并承担相关成本）。
② 智能体应用开发框架：
用于高效构建包含 RAG、工具调用、工作流管理的智能体系统。
● LangChain / LangGraph：功能全面，生态成熟，适用于复杂链式调用和状态机设计。
● LlamaIndex：专注于 RAG 和数据索引，在知识库构建方面有强大优势。
● 自主架构：允许团队使用 FastAPI、Flask 等 Web 框架结合 SDK 自行构建。
